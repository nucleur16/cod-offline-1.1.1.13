# Native news refresh ownership and proof

The implementation consists of the three root news-refresh files, included and installed by kernel33.c. This document records the offline ownership proof; no AS change is needed. Source functions are identified by retained C1 disassembly; the exact guarded bytes additionally match the shipping `a5a7b44e66ca72da785eae4319126c23491586dc88dde499e8e6c9cf4bd6a976` executable.

## Retained objects

The manager pointer is the existing native `0x06C1B29C`; the frame is the existing zero-argument `0x005BC9E0`, called at `0x006B67AA`. The native frame saves/restores ESI itself. Its caller does not consume EAX or flags afterward; the wrapper uses the normal i686 C calling convention. The only additional call of the frame occurs synchronously when a refresh consume has just reached state6, to run its original publisher before returning.

Manager geometry is constructor/usage measured: kind+4, state+8, category+12, embedded HTTP+16, queue head+0x478, tail+0x47c, cursor+0x480, receive buffer+0x484/capacity+0x488/length+0x48c. Node geometry is URL+0, next+4, payload+8, size+12, payload kind+16, category+20, image ID+24. Node kind1 is binary image; kind2 is decoded text. Original native enqueue allocates the 0x1c node and its URL, and cleanup frees those and each retained payload.

The refresh chooses the last configured adnews text URL, matching the original publisher's last non-null text selection. The URL is reused verbatim, including its locale query and normal route. It does not construct a second endpoint, re-read publisher config iterators, reconstruct the manager, or allocate another queue. All image nodes, image bytes, IDs, URLs and their ownership remain native and unchanged. All complete node bytes for both retained images are checked unchanged in the execution tests.

Only the manager's existing request-kind discriminator gains an internal extension value `NR_KIND`. The complete manager vtable contains destructor `5BC4A0` and body callback `5BC790`; the inspected native manager methods write kind0 during construction, kind1/2 during URL classification, and read it only in consume's kind==1 branch at `5BCDA9`. Every other kind follows the existing text parser. The body callback changes state+8, not kind+4. Therefore the marker survives asynchronous body delivery, while the original constructor clears it on every reconstruction, including same-address allocation reuse. No saved node, URL or payload pointer survives a wrapper call. Only a manager-address/timer scheduling hint persists, and it cannot authorize an in-flight mutation.

## Synchronous consume transaction

The original HTTP client's pending-task field at manager+0x2c is read by native `A3F810` to reject overlapping starts. The refresh waits for the same zero boundary before consuming final status or retiring any payload. Callback execution cannot traverse a temporarily changed queue at this point: that native HTTP task has retired, and the original `5BC790` callback only appends receive bytes and changes state.

During the synchronous original consume call only, selected text node.next is temporarily zero. Consume advances the cursor to zero and sets state6. The next link is restored immediately, before calling the original publisher. Thus publication sees the original complete image list, without starting image HTTP again. No link is left changed across a frame, callback, UI input, teardown or return.

The original text parser at `5BC700` allocates a new text payload and overwrites node.payload only for a valid BOM body; it does not free the previous allocation. The wrapper remembers that previous pointer only as a stack local, lets the original consume and publication execute, then retires the old allocation through the exact native CRT free `ADC0B8`. A failure, short response or invalid BOM leaves the previous pointer intact, so nothing is freed and normal publication retains the last good body. The receive buffer is reused and owned by the original manager throughout. No refresh allocation remains outside the original node.

The text handed to AS is copied into the VM at normal publication. This is supported by the exact original publisher itself: `5BCBD6..5BCBDC` passes the news pointer as a type6 string to ObjectInterface vtable+0x14; `5BCC03..5BCC33` passes its **stack-local** image CSV through the same type6 setter. That CSV's stack ceases to exist when this original function returns, so the setter already has to copy/intern an unmanaged C string synchronously. The local Scaleform source reference independently shows ObjectInterface.SetMember -> GFxValue2ASValue -> StringManager.CreateString for unmanaged VT_String (`launcher/3rdparty/Scaleform43/Src/GFx/AS3/AS3_GFxValueImpl.cpp:1733-1744`). The source reference is supporting contract evidence, not a claim that C1 is this exact SDK revision. The execution harness models this VM boundary explicitly, then poisons freed text storage and verifies that rendered text survives. It executes the full original category publisher, not a replacement publisher.

## Zero-body progress

The original manager normally reaches state3 in its first body callback, so no-body completion/failure can leave it in state2. After a **real native start**, the refresh follows the measured HTTP status/pending fields: status1 or a pending task means polling; status2 with no task means success; failed/setup-incomplete means failure. No response or successful publication is fabricated. Status5 is measured in native setup at `A3EA56`; real start sets status1 and pending at `A3F916..A3F91D`; failure to start sets status3/pending0 at `A3F94C..A3F953`. The original initial queue is passed through unchanged; this correction is restricted to refresh requests owned by this feature.

## Verification boundary

`test_native_lifecycle.py` loads the retained exact image in Unicorn and calls the actual C policy through a compiled shared library. Native dispatcher, URL request setup, response callback/buffering, status getter/poll, parser, consume, full publisher, and cleanup execute unchanged. Only HTTP transport, CRT allocation/string helpers, and GFx VM operations are explicit boundary doubles. This is not real C1/HTTP/UI acceptance.

The positive contour covers 21 consecutive updates per locale, constant live payload count, original image/node bytes, publication-before-old-free order, poisoned old allocation safety, actual native cleanup with no double frees/orphans, malformed/empty/failed responses, localized no-news fallback, pending HTTP, setup failures, same-address reconstruction, initial native queue, cyclic queues, and tick wraparound. Three independent negative builds remove refresh, remove retirement, or remove zero-body progress; each fails the relevant regression. Every guarded byte is independently mutated to ensure its fingerprint rejects the mutation. The module compiles warning-free as i686 Win32 C using the current component's helper signatures.

Current `feed_http.py` already responds to an empty news set with BOM plus localized nonempty text (`暂无新闻。` / `No current news.`), so its existing AS truthiness guard accepts that normal fallback. No empty-body AS alteration was introduced. An actual zero-byte/invalid upstream response instead preserves last good news.

Actual same-process EN/ZH acceptance and the normal paired client build/release checks remain separate qualification steps. Offline logs never substitute for observing a genuine refetch, task1480 delivery and changed news in each retained C1 process.
