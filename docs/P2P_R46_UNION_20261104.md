# Isolated r46/P2P client source union

This candidate merges the uninstalled r46 migration candidate
`b18a24f32729ac126d306eccea5e508596c29d94` with P2P source
`410d1ccfa60dc1377e00664b845f991b41533133`. It is source/build work only;
no client, runtime or production package was installed or launched.

Baseline correction: the actual public r45 client source is
`96d7020d8133d854d4be04dd76eda47ef4474a49`, an ancestor of this union.
Its frozen public Kernel33 SHA256 is
`f4b6a547d8bb2dd8242e575929a32588373c36908e0339fddd3a3c91a006413a`.
The b18 source and thirteen protected hashes are a candidate parity reference,
not evidence that the migration or this P2P combination was deployed.

The repaired `kernel_call_guard.c`, all `kernel_name_*` and `kernel_room_*`
components, `kernel_video_mode.c`, `borderless.c`, `production_profile.h` and
`build-profile.sh` remain byte-identical to the b18 candidate. Migration switches stay
off by default. Explicit migration excludes the P2P legacy name/room publishers
so both implementations cannot own the same hooks. Developer console/vision
remain available only under explicit diagnostics. Native build libraries include
the requirements of both parents.

Pi's first-priority VEH previously could consume a nested CRT AV before the
migration call's thread SEH fail-fast. The Pi-side exclusion now recognizes the
actual `KrcCallException` registration through a bounded64-node current-thread
SEH chain read. Active markers, invalid links or unreadable records decline
rescue. Ordinary server faults without a migration marker retain Pi rescue.
The repaired candidate guard itself is unchanged. Sixteen compiled x86/Unicorn
tests pass, including exact native Cbuf/Dvar instruction and lock behavior.
The same nested-CRT test fails with the original410 Pi handler. Windows exception
dispatch/thread/fiber APIs remain modeled; this is not Windows/game acceptance.

Five conflicting movie classes were recompiled from the merged AS3 with FFDec;
conflicting parent binary outputs were not used as the final classes. The
candidate baseline records these source/tag bytes while retaining its
unqualified-candidate status. Map/mode tests pass on source and actual compiled
exports; training controls, Local Play checkbox placement, eight viewport
layouts, four ticker categories and monitor lifecycle checks pass. Production
map rows are retained and P2P-only Survival selections have unique row IDs.

Two live-class assertions in the invitation-history suite remain blocked: they
expect the historical MatchController ABC table/body bytes to equal the newly
compiled P2P/r46 class. The immutable99-check recompile and22-check integration
snapshots and168-case invitation behavior checks still pass. Historical proof
files were not rewritten. The production b18 ABI contract is retained separately
as `abi-contract.production-b18.json` (a historical filename for the uninstalled
candidate); the canonical P2P historical contract
retains its review-chain fields. Current compiled-class ABI review is still a
release gate, not waived by refreshing the candidate source/tag pins.

The legacy Ready/native-start ordering is preserved for the next explicitly
owned adapter step. This union does not resolve distributed principal ingress,
the startup/Ready cycle, active-match authority or safe rehost gates. Root-owned
new startup wire/bridge files are excluded from this merge commit. The tracked
Kernel33 DLL is retained from the production parent; no new DLL qualification
is claimed. All original worktrees and the active Host remain untouched.
